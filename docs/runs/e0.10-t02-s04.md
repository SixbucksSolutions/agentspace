# E0.10-T02-S04 run record: the workspace tests that hang or fail under load (#0191, #0189), 20 runs each beside a load

RFC 2119 keywords; the capitals are load-bearing.

The evidence for card #0217 (epic #0050, v0.10-T02): six test targets, each run 20 times on the
branch's build beside a parallel workspace build and a conformance suite run, and every run finishing
and passing. Every time below is 2026-11-24, in Mountain Standard Time (UTC-07:00), the laptop's zone.
Branch `v0.10/e0.10-t02-s04` at 116687b, on main's b9710f6, when these runs were made.

**The headline: 120 of 120 runs finished and passed, 20 of 20 for each target, every exit code 0, no
run hung (the longest was 128.13 seconds against a bound of 420), and no "16-Bit" dialog was seen
before or after any run or lane. They ran inside one load window, 5:43:23pm to 6:10:19pm.**

## What #0217 is

- **#0191:** four targets waited, for minutes or for ever, on a modal "Unsupported 16-Bit
  Application" dialog on the desktop. The dialog is a hard error CreateProcess raises on the calling
  thread, when a file named `.exe` is not a PE image and the process's error mode has
  SEM_FAILCRITICALERRORS clear. With it set, CreateProcess returns error 216 at once (the diagnosis'
  probes, 4:25pm: 16 to 146 ms, no dialog).
- **What each target starts:** `spec_launcher` writes "Not a program." to `not-a-program.exe` and the
  launcher starts it; `agentspace-run`'s `rulings` and `seam` start `.cmd` stand-ins and renamed text
  files as `ssh.exe` and `scp.exe`; the operator's `seam_and_hygiene` AWS-variable test plants a text
  file as `not-a-program.exe` and the operator starts it through `agentspace-run`.
- **Why it showed in T02:** a process started by `Start-Process -WindowStyle Hidden`, which is how the
  T02 run wrapper started runs, has error mode 0, and so do its children. A pwsh from a subagent's
  PowerShell tool has 0x8003 and from its Bash tool 0x3. Nothing on these paths, no toolchain and no
  Windows hotfix changed since e0.08-t04-s04 (2c7e2c5); the launcher was the difference found. Which
  parent e0.08's runs had is not recorded, so that last step is inferred.
- **#0189:** wall-clock assertions in the story's crates failed under load.

## The fixes

- **The wrapper (4:28pm):** `t02-run.ps1` sets error mode 0x8001 before its command, and each run's
  `.times` file logs it. That is the dev lead's tool and not a repo file.
- **Option B, the architect's ruling at 4:31pm:** `SetThreadErrorMode` adds SEM_FAILCRITICALERRORS
  and SEM_NOOPENFILEERRORBOX around every CreateProcess, restored on Drop. It is in `agentspace-launch`
  `src/win/spawn.rs` (`NoErrorBoxes`, both create calls) and in `agentspace-run` `src/win.rs`, around
  the single start site in `start`. Option C, a PE check before starting (622d64c, ad89ce4), was
  removed by 90ec37a. `agentspace-launch` adds `pub fn quiet_hard_errors()` (P21), which T03 calls
  from the operator's, the ssh proxy's and the three keeper programs' mains (#0226) and the CLI's
  (#0219), by D81's change during v0.10-T02. keeper.md (fab0595) says a start MUST NOT wait on a
  Windows dialog.
- **Tests from error mode 0, each proven to fail on the unfixed code once:** `agentspace-run`
  `tests/no_dialog.rs`; the operator's
  `an_aws_variable_naming_a_file_that_is_no_program_fails_at_once_with_no_dialog` (the operator
  started with CREATE_DEFAULT_ERROR_MODE); `agentspace-launch` `tests/spec_launcher_no_error_box.rs`
  and `tests/spec_quiet_hard_errors.rs`.
- **The stand-in's cost:** `agentspace-run` `tests/common/mod.rs` starts 2 processes a call, and
  `tests/standin_cost.rs` counts starts by job accounting and failed at 4 on the old code.
- **#0189, `spec_stop`:** the exit-time ordering check is removed. The call order stays checked by
  `src/process.rs:614 the_whole_tree_is_stopped_leaves_first_and_the_holder_last`.
- **#0189, `spec_launch_withdraw`:** the create-fails bound is now the watcher's request-to-withdraw
  gap under 35 s. In the same file, the unanswered-request spec
  (`an_unanswered_request_is_withdrawn_with_abandoned_at_35_seconds...`) had two bounds, 34.5 to 42 s
  around the whole start and a 34.8 to 36.5 s gap; they became one, the withdrawal measured from the
  request's `not_after` minus 30 s, 34.95 to 38 s. `read_retry` gives up at once on a file already
  gone.
- **#0189, `spec_launcher`:** the error cases are bounded at 60 s (`launch_within_bound`), and the race
  specs' holder-line wait went from 3 s to 20 s.
- **#0189, the operator:** `grow.rs` is timed from the stand-in's clock (proven by a planted 10 s
  wait), and `status_leases`, `deploy_passthrough`, `seam_and_hygiene` and `up_push` take the rig's
  90 s limit. `agentspace-run` has no wall-clock assertion.
- **Commits as run, on b9710f6:** ad89ce4 (option C, later removed), 178d040 (operator test
  bounds), 90ec37a (option B), aa47d0a (launch and keeper-win), cd9e032 (run tests: the stand-in's
  cost), 116687b (launch: both bits at every create, `quiet_hard_errors`).
