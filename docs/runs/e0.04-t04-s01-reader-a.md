## 1. How I would build a drop-in

### 1.1 The lease CLI (`agentspace lease ...`)

**One Rust binary, `agentspace.exe`, Windows only for v0** (lease-api.md Q1 is open; state.md is
written for Windows and `USERPROFILE`). Modules, in build order:

1. **`argv`: the command-line reader** (lease-api.md "Command lines", lines 126-193). A
   left-to-right tokenizer that produces either a help request for a level, a usage error with its
   category (unknown command/subcommand; unknown option, no value, empty value, given twice,
   unexpected argument; missing command/subcommand/ID/`--project`), or a parsed command. The
   precedence rules 1 to 5 (lines 180-193) are implemented as a two-pass scan: pass 1 finds the first
   `-h`/`--help` in any case before an unknown command or subcommand, including in a flag's value
   position; pass 2 reports the first error by category, then by line order. `--flag=value` always
   gives a value; `list --state` is the one repeatable flag. Help blocks are embedded byte for byte
   from lease-api.md (lines 584-977), each line ending in LF.
2. **`values`: the normalizers** (lines 390-507): lease ID, project, platform, profile, size, TTL
   (short form and ISO 8601, overflow is `out_of_range`), state filter. Trimming uses the Unicode
   `White_Space` set (A-16). Every match is whole-value, ASCII-only for letters and digits. Each
   normalizer returns `invalid_value` or `out_of_range` with the message template of lines 1060-1093
   chosen by the rules given there (the TTL's three message cases included).
3. **`output`: JSON writers** (lines 76-106, 1007-1093): compact UTF-8, no BOM, one LF; members in
   table order; fields omitted, never `null`; error document to stderr with `field`, `lease_id` and
   `state` exactly as lines 1010-1020 require, the five `usage` cases carrying `field`; control
   characters in quoted values written as `\u000a`-style text. Exit codes 0 to 4 (line 981).
4. **`paths`: the home folder** (state.md lines 52-86): `USERPROFILE` read from the environment
   only, made absolute; `<state folder>` and `<ssh folder>` from `AGENTSPACE_STATE_DIR` and
   `AGENTSPACE_SSH_DIR`; a value naming a file fails `internal`.
5. **`store`: the lease state file and its lock** (state.md lines 237-346, 1113-1135): open
   `leases.lock` with share mode 0, retry up to 30 seconds (A-18), then `internal` "busy". Read
   `leases.json` with read/write/delete sharing, tolerate a BOM and whitespace, validate against
   `schemas/state/leases.state.schema.json` (embedded) on read and before write, write through
   `leases.json.<hex>.tmp`, flush, `MoveFileEx(REPLACE_EXISTING)`. Derive `expired` on read. Read a
   `ready`/`released` record with no `driver` as `ec2`, never add or change the member.
6. **`ca`: the CA check, never creation** (state.md lines 766-861): both files, owner-only folder
   then key (owner SID equals the token's user SID, `SE_DACL_PROTECTED`, exactly one allow ACE for
   that SID with `0x1F01FF`), key unencrypted (cipher and KDF `none`), public key's first two words
   equal the derived ones and the first is `ssh-ed25519`, public key parses.
7. **`credential`: key and certificate** (state.md lines 357-452): ed25519 key pair in OpenSSH
   formats written natively (the `ssh-key` crate or equivalent), no passphrase, comment
   `agentspace lease <id>`, private key ACL set and checked (A-22); a user certificate signed with
   the CA: serial 0, key ID = ID, one principal `ubuntu`, valid-after = issue time minus 5 minutes,
   valid-before = issue time plus TTL, extensions exactly `permit-port-forwarding` and `permit-pty`.
   Renewal through `renew-<hex>*.pub` files in the order of state.md lines 656-671.
8. **`sshconfig`: the `Include` line and the alias file** (state.md lines 453-595): the line finder
   and inserter (BOM, CR LF detection, backup `config.agentspace-backup-<YYYYMMDDTHHMMSSZ>` with a
   SHA-256 check, `ReplaceFile` to keep the config's own ACL), and the alias file written byte for
   byte from the template at lines 465-478 through `<ssh folder>\<alias>.agentspace-tmp-<hex>`, with
   the owner-mark rules for an existing file.
9. **`driver`: the boundary and the EC2 driver** (driver.md): an in-process trait with `place`,
   `renew` and `release`, each returning a result or a `Failure { message, cause }`; the CLI wraps
   every failure as `agentspace lease <sub> failed: <message>`. The EC2 driver supports exactly
   `linux/arm64`, `agent-linux` and `m`, and computes the transport (A-01, A-03).
10. **`commands`: `create`, `get`, `renew`, `release`, `list`** wiring the above in the orders of
    driver.md lines 198-220 and state.md lines 605-722, with every failure path's leftovers as the
    tables there say.

**Checked against:**

### 1.2 The operator (`deploy`, `up`, `sync`, `ca`, `down`, `status`, `grow`, the ProxyCommand, the push)

**One Rust binary for the operator commands, and a ProxyCommand program** (operator.md Q10 leaves
the names open; conformance passes PowerShell-style arguments such as `ca -Quiet`, so I would keep
them). Modules, in build order:

1. **`cli`**: the parameter reader (operator.md lines 69-111): case-insensitive command and
   parameter names, `-GiB <n>`, `-Alias <alias>`, `-Quiet`, help first at every level, then the
   `-Alias` checks with the exact messages of lines 104-111, then the other usage errors with exit 1

2. **`env`**: remove every `*_POSIX_FD_STATE` variable, set `AGENTSPACE_NESTED=1` for children, read
   `USERPROFILE`, `LOCALAPPDATA`, `SystemRoot`, the OneDrive variables, and the test seam variables
   (`AGENTSPACE_AWS_CMD`, `_SSH_CMD`, `_SCP_CMD`, `_TIMEZONE`) at the moment each program is needed
   (lines 234-332).
3. **`proc`**: starting programs: full paths for `ssh.exe`, `scp.exe`, `ssh-keygen.exe`,
   `icacls.exe`, `taskkill.exe`; the AWS CLI at its fixed path then `PATH`; stdin a pipe or closed,
   never inherited by `up`'s children; stdout of `up` never written; the 20-second tree kill.
4. **`aws`**: every call of the table at lines 1412-1422 with `--region us-west-2` and `--output
   json` where read; the sign-in test and its exact message (lines 202-214); JSON parsing of
   `describe-instances`, `describe-volumes`, `describe-instance-information`, `send-command`,
   `get-command-invocation`.
5. **`cache`**: the instance-ID cache at `%USERPROFILE%\.agentspace\instance-id`, rebuilt from
   `describe-stacks`' `InstanceId` output; empty counts as missing (lines 357-367).
6. **`ca`**: create once (refuse elevated, lock the folder with one inheritable ACE before the key
   exists, make the key, lock it), then the five checks of state.md "Its checks" with `ca`'s own
   messages and the `<problems>` list (lines 614-712; A-23).
7. **`wait`**: start and wait (lines 816-849): the state machine for `stopped`/`stopping`, the
   20-minute launch-time rule, the 15-minute wait with a 5-second poll of SSM and the patch-check
   Run Command (lines 1322-1350), messages printed only when they change.
8. **`push`**: the token push (lines 959-1242): read the receipt and `bot.xml` (A-12), the zone
   (Windows ID to IANA through ICU or a CLDR table, the seven legacy names, the zone regex), the
   stamp, the ssh with `-o ClearAllForwardings=yes -o BatchMode=yes <alias> <remote command>`, the
   box-side command written to the step list of lines 1136-1177, the confirmation rules, every
   warning text, and secrecy.
9. **`commands`**: `deploy`, `up`, `sync`, `down`, `status`, `grow` as their sections say.
10. **`proxy`**: the ProxyCommand (lines 851-957): refuse a second argument, prepend the two
    folders to `PATH`, run `up` in caller mode (A-13), read the cache, run `ssm start-session`, exit
    with its code, restore the console mode, and keep backend text out of stderr unless
    `AGENTSPACE_DIAGNOSTIC` is set.

**Checked against:** `conformance/operator/test-alias-refusals.ps1`,
`test-proxy-arguments.ps1` and `test-unmet-proxy-connect-time.ps1`, with `AGENTSPACE_OPERATOR_CMD`

### 1.3 The keeper

**One Rust binary, a Windows-subsystem program, so that the scheduled task needs no separate
launcher** (keeper.md Q8 open). Modules, in build order:

1. **`args`**: the argument reader and the usage errors in the order of the table at keeper.md
   lines 222-235, three lines to stderr, exit 2; the hidden `-FastFailureSeconds` accepted
   (conformance.md Q1).
2. **`files`**: state folder resolution, the JSON writers (compact, no BOM, LF, atomic through
   `<name>.<hex>.tmp` with the 50 ms / 5 s rename retry), the record reader that treats anything
   malformed as no record, and the log writer that appends each line atomically with
   `FILE_APPEND_DATA` (keeper.md lines 884-971; state.md lines 891-1043).
3. **`locks`**: `board-holder.lock` (share none, 100 ms retry for 10 s, then `skipped`) and
   `board-holder-keeper.lock` (share read, PID written, one try), handles not inheritable
   (keeper.md lines 826-882).
4. **`matcher`**: the `CommandLineToArgvW` splitter, the cmd `/c` quote rule, path normalization and
   comparison, and the self-check table of lines 397-422 run at the start of every pass.
5. **`procs`**: open by PID with limited query rights, read creation time and command line, walk
   children by parent PID with the creation-time check, terminate leaves first, 2-second waits, 5
   rounds (lines 431-482).
6. **`launch`**: the handshake of lines 541-618 (request, WMI `Win32_Process.Create` of the keeper
   itself as launcher, claim with `CREATE_NEW`, result, withdrawal, removal), and in launcher mode
   the holder's creation with `NUL` stdin, one append-only shared log handle, no window, new process
   group, `%USERPROFILE%` as its working folder, outside the pass's job (A-07, A-26).
7. **`pass`**: the eight steps of lines 280-304: lock, matcher check, log rotation, lease state
   (validated against the state schema), ready leases, trust, act, unlock; one action line.
8. **`watch`**: the loop of lines 659-807: look, pass, tracking table, `-MaxPasses`, waits with the
   backoff formula, the release grace and the #0068 rule, and no error ever ending the loop.
9. **`install`**: the task registration (lines 998-1177) through the Task Scheduler COM API: two
   triggers, the fields in the table, the worktree refusal, the running-keeper refusal, `-DryRun`
   and `-Uninstall` (A-10).

**Checked against:** `conformance/keeper/test-keeper.ps1` (42 cases, including the launch files
