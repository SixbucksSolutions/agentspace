### Finding 1: the task's repeating trigger started the old keeper before the install ended

The four times, from the wrappers: stop 5:20:11pm; the trigger's keeper, pid 46892, 5:20:12pm; install
end 5:20:14pm; `Start-ScheduledTask` 5:20:14pm, which changed nothing, because the task was already
running. That is why two files were in use at the copy, and why the keeper that ran was the old build.
It is the race keeper.md, "Stopping and starting the keeper", names. Wrapper 3 found it, exit 1.

- **The remedy, on the dev lead's go, was keeper.md's own steps** (wrapper 4, exit 0): pid 46892 was
  checked as the keeper (the lock held and giving that PID, the installed program, started
  5:20:12pm); End at 5:21:37pm; stop at 5:21:40pm; `Start-ScheduledTask` at 5:21:40pm. The task was
  not disabled and not re-registered. Wrapper 5 (exit 0) then showed pid 46020 started 5:21:41pm,
  after the install's end.
- **What it stops:** a single stop-install-start pass. An install over a keeper whose trigger can
  fire inside the install needs the keeper checked after it, as wrapper 3 did, and a second stop.
