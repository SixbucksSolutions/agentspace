## Crate tests that ran the removed shim

**The Reviewer (Opus/high) found that two crates' Windows tests started
`conformance/prototype/operator.cmd`** to make each throwaway CA. The path was built from pieces
(`.join("conformance").join("prototype").join("operator.cmd")`), so a search for the file's path
missed it. With the shim removed, `agentspace-driver-ec2`'s fixtures would have panicked and
`agentspace-credential`'s `operator_made_ca_passes_check_ca` would have failed.

- **The ruling** (architect, 2026-11-20, for E0.06-T06-S01): fix both crates' test helpers in this
  pull request, since removing the prototype MUST NOT leave `main` failing its own tests. Each
  helper makes the CA in process through `agentspace_ca::ca`, as agentspace-sync's tests already
  do, with `agentspace-ca` and `agentspace-operator-api` as dev-dependencies only. Its `Context`
  names the throwaway home, no `LOCALAPPDATA` and the real `SystemRoot`; its `CaEnv` carries
  made-up user and computer names and no OneDrive folder. No real `USERPROFILE`, `LOCALAPPDATA` or
  `APPDATA` reaches either.
- **`Cargo.lock`** gained only those four path entries, added by cargo offline, not regenerated.
- **`cargo fmt --check --all`:** clean.
- **`cargo clippy --workspace --all-targets --locked -- -D warnings`:** exit 0, from 7:56am.
- **`cargo test --workspace --locked`**, in full on Windows, from 7:56am to 8:09am: **exit 0; 188
  test binaries, 2,883 passed, 0 failed, 50 ignored.** Every ignored test is a helper that another
