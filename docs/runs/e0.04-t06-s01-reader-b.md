## 1. How I would build a drop-in

### 1.1 The lease CLI (v0.05)

**Files shipped:** `agentspace.exe`, the `agentspace` wrapper (`#!/bin/sh`, LF, turns MSYS path conversion off and runs `agentspace.exe` beside it with `"$@"`), and the one-line forwarder `agentspace-ssh-proxy.cmd` (operator.md, "Until v0.06 retires the prototype's entry points").

**Modules, in one Rust crate:**
- `args`: The left-to-right tokenizer of lease-api.md "Command lines": command and subcommand by ASCII letters without case, `--name[=value]`, the next-argument rule, help anywhere, and the five-step "Which error is reported" order.
- `help`: The seven help blocks as byte constants, each line ending in LF.
- `values`: One normalizer per value (lease ID, project, platform, profile, size, TTL in both forms, state filter), sharing one `White_Space` set and whole-value matching.
- `output`: Compact JSON writer, member order as the Fields table, the error document, the control-character escape for quoted values, and every message template of "Messages".
- `paths`: `USERPROFILE`, `AGENTSPACE_STATE_DIR`, `AGENTSPACE_SSH_DIR`, made full before any is written into a file.
- `state`: `leases.json` read with read, write and delete sharing; the state schema carried inside the program; the duplicate-ID check; the atomic replace through `leases.json.<hex>.tmp` with a 10-second rename retry; `leases.lock` opened with share mode 0 and retried for 30 seconds; `expired` derived at read time.
- `driver`: A trait with place, renew and release, a failure of message and cause, and an opaque name. One driver, named `ec2`, compiled in.
- `credential`: The five CA checks of state.md "Its checks" (a Windows owner-only check by SID, protected DACL, one full-control allow entry), an ed25519 pair in OpenSSH format with no passphrase, the three-entry key rules, and a user certificate with the exact fields of state.md "The certificate", valid-after back-dated 5 minutes.
- `alias`: The `Include` line scan and insertion (backup, SHA-256 check, `ReplaceFile`), the alias file's bytes and owner mark, the default ProxyCommand line found beside the executable.
- `commands`: `create`, `get`, `renew`, `release`, `list`, with renew's eight-step order and release's record-first order from state.md, and create's cleanup that names leftovers as `~/.agentspace/leases/<id>/...`.

**Order, and what each step is checked against:**
1. `args`, `help`, usage errors: `test-help.ps1`, `test-usage-errors.ps1`.
2. `values`: `test-values.ps1`, and `conformance/schemas/test-schemas.ps1` for the package itself.
3. `state`, `get`, `list`, unsatisfiable `create`: `test-list.ps1`, the unsatisfiable halves of `test-create-get.ps1` and `test-lease-driver-outcomes.ps1`, `leases.state.schema.json`.
4. CA check, credential, alias, ready `create`: `test-create-get.ps1`, `test-lease-certificate.ps1`, `test-lease-alias-file.ps1`, `test-unmet-no-ca.ps1`, `test-unmet-default-transport-no-cache.ps1`, `test-unmet-include-message.ps1`, `test-unmet-failed-create-cleanup.ps1`.
5. `renew` and `release`: `test-lease-cmd-renew-release.ps1`, `test-unmet-renew-keeps-certificate.ps1`, `test-unmet-release-partial.ps1`, `test-unmet-release-released.ps1`, `test-unmet-record-no-driver.ps1`, `test-unmet-internal-no-path.ps1`.

8. One run sharing a home with the prototype, by the checklist of state.md "Between the prototype and the rewrite", and the whole suite once on a machine whose zone is not UTC.

**Throughout:** `AGENTSPACE_CMD` names `agentspace.exe` in the build's output folder, `AGENTSPACE_OPERATOR_CMD` stays the prototype's shim so the harness can make its throwaway CA, and a program that prints nothing is run first to see every check fail.

### 1.2 The operator (v0.06)

**Files shipped:** `agentspace-operator.exe` and `agentspace-ssh-proxy.exe`, with the forwarder rewritten to the `.exe`.

**Modules:**
- `cli`: The operator's own parse (help first, then left to right, then the two `-Alias` checks), its seven usage messages, exit 1, and the eight help texts.
- `msg`: Everything to stderr, `-Quiet`, and a caller mode that swaps each line by the two tables of "What a caller sees".
- `procs`: Program lookup by fixed path, the three seam variables read at the moment of use, the removal of every `*_POSIX_FD_STATE` variable, `AGENTSPACE_NESTED=1` for children, a closed or piped stdin for every child.
- `aws`: One call builder (`--region us-west-2`, `--output json` where marked), the sign-in test, and the JSON members of "What is read from each answer", each read only by the command that uses it.
- `cache`: `%USERPROFILE%\.agentspace\instance-id`, empty counted as missing.
- `startwait`: The four steps of "Starting the box and waiting for it": 15 minutes, 5-second checks, the patch question through Run Command, polled once a second for 20 seconds.
- `push`: The receipt reader (BOM-chosen encoding, strict JSON, two members without case), the CLIXML reader, `CryptUnprotectData`, the zone (CLDR conversion, seven legacy names, the zone pattern, `AGENTSPACE_TIMEZONE`), the stamp, one ssh with a 20-second clock and a tree stop, and the two confirmations.
- `ca`: Creation and the five checks with `ca`'s own messages and `<problems>` list.
- `assets`: The stack's template and `box\system`, carried in the binary and written out under `%USERPROFILE%\.agentspace\operator` at use.
- `deploy`, `sync`, `status`, `down`, `grow`: Each as its numbered steps, with its own remote commands written fresh from what each step MUST do on the box.
- The proxy binary: second-argument refusal, `PATH`, `up` in caller mode, the cache read, the tunnel with its stderr withheld unless `AGENTSPACE_DIAGNOSTIC`, and the console mode.

**Order, and checks:**

### 1.3 The keeper (v0.06)

**Files shipped:** `agentspace-keeper.exe` (console), `agentspace-keeper-task.exe` (no console), `agentspace-keeper-install.exe`.

**Modules:**
- `args`: The six ordered usage checks, three stderr lines, exit 2, the hidden `-FastFailureSeconds`, the `SystemRoot` default for `-SshExe`.
- `log`: The line grammar, whitespace as `_`, the reason rules, one atomic append per line with five tries, the stdout copy.
- `locks`: `board-holder.lock` (10 seconds, 100 ms) and `board-holder-keeper.lock` (one try, the PID read back), neither handle inheritable.
- `leases`: A read-only reader of `leases.json` with the state schema carried inside.
- `proc`: Open by PID with limited-query and wait rights, creation time to the millisecond, command line, the tree walk by parent PID with the creation-time check, leaves-first stop.
- `matcher`: The `CommandLineToArgvW` splitter with the quote-run count, rules 1 to 5, and the self-check table run at every pass.
- `pass`: The eight-step order and the five-row action table, rotation at 1 MiB.
- `start`: The handshake: request, a launcher created through WMI's `Win32_Process.Create` with a 10-second bound and three tries, the 35-second wait, the withdrawal by claim, the 60 more seconds, the one check of the holder, removal in order, then the record and the `started` line. The launcher is the keeper's own program under a hidden argument: it claims with `CREATE_NEW`, honors `not_after`, and creates the holder with `NUL`, one append handle, no window, a new process group and a breakaway from its job.
- `watch`: The look, tracking, proof at 60 seconds, the fast-failure count, backoff, release grace, the `lost` rule of #0068, and the floor of `-IntervalSeconds` on every path.
- The task launcher and the installer: As keeper.md "The task's launcher" and "The installer".

**Order, and checks:** `args`, `log`, `locks`, then the one-pass cases (idle, unreadable state, lock busy, bad `-Now`), `matcher`, `start`, keep and stop, rotation, `watch`, #0068. All against `conformance/keeper/test-keeper.ps1` (42 cases, then `-SelfCheck`) and `test-unmet-holder-dies-mid-pass.ps1`, with the three `schemas/state/board-holder*` schemas through the suite's schema case. The task launcher and the installer have no check and no conformance variable, so `-DryRun` is compared with keeper.md by eye, and a real install waits for Terry's yes.

**What was looked for and not found:** No command, flag, output field or exit code of the three interfaces lacks a definition. No environment variable a program reads is unnamed. Every timeout and retry a check can see has a figure. No "Open questions" entry in a spec doc is left unmarked.

## 4. Verdict

`VERDICT: YES`

**A drop-in of the lease CLI, the operator and the keeper could be built from the export, with no blocking guess left.** All 27 gaps are `minor`: a careful builder gets each right, or the difference cannot be seen from outside, or a conformance check in the export shows the answer.

**One condition rides on the YES, and it is FB-01.** The operator's `deploy` and `sync` ship two things the export does not hold, the stack's template and `box\system`. operator.md says to carry them from the repository, so no guess is needed, but the build needs those two paths as opaque inputs. If the architect reads "from the export alone" as excluding even that, FB-01 becomes the one gap that blocks, and the fix is a sentence in operator.md saying that the rewrite embeds both unread and MUST NOT re-author the template.
