## The plants

**Each edit is shown load-bearing by a check that FAILs on the unmasked line and passes on the masked one.** Both checks
run against two trees of the `conformance` folder, extracted with `git archive` into `target\s04-lead\plants\`: `base`
from `ff0356e` and `head` from `415c9eb`. **Each check plants an environment before it loads the harness**, so that the
mask is built from it: `USERPROFILE` and `HOME` name a folder `home\Users\plantuser-s04` under `target\s04-lead\plants`,
`USERNAME` is `plantuser-s04`, `COMPUTERNAME` is `PLANTPC-S04`, and `TEMP` and `TMP` a folder beside it. **Nothing of the
real profile is read, and each check prints booleans and counts only.** The plants are not committed.

- **Plant 1, the start error** (`planted-start.ps1`): it calls `Start-ConformanceProcess` on a program that does not exist,
  `no-such-folder\planted-program.exe` under the planted profile, with the planted profile as the working directory. It
  passes only when the result is the start error (`ExitCode` -1, `Stderr` beginning `Could not start the program: `), its
  `Stderr` holds no `plantuser-s04` and holds `%USERPROFILE%`.
- **Plant 2, the passed-through line** (`planted-passthrough.ps1`): a child pwsh loads `keeper-common.ps1` and calls
  `Initialize-KeeperRegistryMode 'Both'` on a planted keeper file, `planted-child.ps1`, which prints one line that is
  neither a result nor the summary, `Planted passed-through line: <the planted profile>\planted-secret.txt`, then a `PASS`
  line and its summary. `-Registry Both` runs the child once for each mode, so the line passes through twice. The check
  passes only when the inner run exits 0, both passed-through lines are there, no output line holds `plantuser-s04` and
  both hold `%USERPROFILE%`.
